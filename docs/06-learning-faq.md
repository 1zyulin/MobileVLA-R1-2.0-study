# 学习过程中的常见问题

## 我究竟在学什么、实验什么？

先学会把模型、素材、训练和评测区分开。当前实验检验工程链能否成立：选对底座、连接真实观测与标注、得到合法输入、完成参数更新、保存结果。后面的研究实验才检验某种训练方法是否提高任务能力。

可以把原始数据看作教材，把底座看作已有知识基础的学生，把训练看作做练习后调整内部参数，把独立评测看作考试。教材下载完和考试得高分之间还有很多工作。

## 下载的 100 多 GB 是什么？

约 124.8GB 是 QUARD 的压缩原始档案，包含多个任务的观测和状态/控制记录。它不是一份已经训练好的模型，也不是按文件大小直接投入 GPU 的单一训练样本。

另有约 17GB 的 NaVILA 底座文件，以及约 755MB 的 MobileVLA-CoT 标注。底座提供初始参数；原始档案提供素材；标注提供推理或监督信息。三者需要正确连接，才能构成训练样本。

## 训练会把所有图片一次塞进显卡吗？

通常按样本或小批次读取，经过编码和模型计算后更新参数。显存主要受模型、参与训练的部分、每条输入长度、帧数和批量大小影响。磁盘上有 124.8GB，不意味着必须有 124.8GB 显存。

但这也不代表任意显卡都够：当前未量化配置的真实前向峰值已约 16.117GiB，而反向传播还有额外开销。

## 为什么先只用一条轨迹、两帧图像？

这是一个有边界的工程检查，目的是确认真实图文数据可以进入训练器并更新参数。大范围学习任务能力之前，先证明最小流程可运行。它没有足够规模支持导航能力、泛化能力或论文指标的结论。

## 作者公开了数据，为什么还要花时间对齐？

公开数据可能来自不同版本的格式：图像引用路径需要重映射；逐步推理要找到正确帧和控制命令；文字动作未必含具体速度；部分标注没有可验证的训练/测试划分。当前实现对动作监督和模态输入有明确要求，下载成功不自动满足这些要求。

缺失的标签不能靠猜测填上。把 step 标注改名为 episode，或把归一化深度灰度直接当米制距离，也不能解决数据含义的问题。

## 本机和实验室服务器有什么区别？

| 设备 | 已核查硬件 | 当前用途 |
|---|---|---|
| Windows 本机 | i7-10700KF、16GB 内存、RTX 3060 12GB | 阅读和编辑源码、Remote SSH、受限的小样本 CPU 检查 |
| Ubuntu 服务器 | RTX 5090，约 32GB 显存，共享使用 | 已完成模型前向验证；准备 GPU 空闲后的小样本训练验证 |

当前配置不能原样放到本机运行：已验证的前向显存峰值高于本机 12GB。量化或卸载是另一个需要适配与验证的方案，尚未在本机做过。

## 显存空着，为什么还要等 GPU？

显存容量和计算利用率是不同资源。其他任务可能只占少量显存，却几乎占满算力。共享使用时，当前实验要求其他 GPU 计算任务退出、连续空闲并满足内存限制后才启动；不终止别人的任务。

## 为什么不是 GPU 一空闲就马上启动？

用户要求降低检查频率，当前常规间隔是两小时。只有到计划检查时发现可能空闲，才做短间隔安全复查。满足条件后启动一次；它不是实时 GPU 调度系统。

## 训练需要多久？

当前两步尝试限时约五分钟，超时退出；这个上限不是已完成训练的实测耗时。

正式训练需要知道有效样本数、轮数、批量、上下文长度，并测量代表性的训练更新速度。计算时间可用“预计更新数 × 稳态每次更新时间”初估，还要另加数据准备、加载、保存、评测与共享 GPU 排队。现阶段不依据 124.8GB 给出几天完成的承诺。作者的训练资源与单张 32GB 5090 不同，详见[后续路线](05-roadmap-and-evaluation.md)。

## 训完会出现什么？

两步验证预期产出有限 loss、参数变化证据、检查点和验证报告。动作解码器在这一步冻结，不能据此声称获得能控制机器人的完整策略。

完整动作训练和环境接入后，要检验的目标是：输入画面和“绕过椅子走到桌边”，模型给出推理与任务层运动指令。之后才可通过实际轨迹、录像和成功率展示效果。这是目标情景，不是当前已经录制的实验结果。

## 为什么 loss 下降不等于机器人变聪明？

loss 衡量训练目标的误差，可能因记住训练样本而下降。机器人任务还涉及观察是否正确、连续行动是否合理、何时停止等。需要在隔离的未见场景中按统一规则评测，才有能力结论。

## 我们已经做域随机化了吗？

还没有。下载带纹理差异的任务数据不等于实施域随机化。未来可设计有/无随机化的训练对照，固定其他条件，在同一组未见纹理、光照或场景上比较；具体方案见[路线与评测](05-roadmap-and-evaluation.md)。

## 为什么现在还不能保证完整复现？

底座前向通过之后，仍有正式数据划分、行为监督、深度/点云、训练显存和环境评测等依赖。当前上游代码也公开说明尚未用该实现复现运行与基准结果。我们会逐阶段记录已验证结果和失败原因，最后以实际评测证据判断完成程度，而不是把流程启动当作论文复现成功。
