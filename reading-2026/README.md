# 2026+ VLA / VLN 论文学习主线

> 核对日期：2026-10-18。**从 2026 年发表/首次提交的论文中选题**；2024–2025 年作品仅列为背景阅读。本专题是未来学习计划，不是已完成实验结果。

## 学习定位

围绕 **MobileVLA-R1 2.0（2026）**建立两条互相连接的路线：

- **A｜推理与动作对齐**：CoT → grounded reasoning → 强化学习/奖励设计 → action head。核心：MobileVLA-R1 2.0、RoboAlign、GroundingVLN、Foresight。
- **B｜导航、部署与控制**：语言/视觉目标 → 空间规划 → 延迟处理 → 轨迹恢复 → 机器人控制。核心：Uni-LaViRA、TIC-VLA、DA-Nav。

我们不是要“把所有代码都跑一遍”。优先做到：**读懂论文 → 可画框架图 → 复述数学目标 → 对照实现 → 做一次可验证的最小实验 → 记录局限**。

## 固定学习约定

1. 每周至少研读 **两篇不同论文**，周三提交学习报告；报告要写明已经读过哪些具体章节，未读的部分标为“待读”。
2. 每篇论文的学习笔记至少回答：**研究问题、输入输出、结构图、公式/损失、数据与指标、创新和局限、与 MobileVLA 2.0 的区别**。
3. 严格区分 **论文作者报告 / 自己复核的源码 / 本地真实实验 / 待验证设想**；不能把作者结果写成本地复现成果。
4. 阅读“有代码”≠“开箱即用”。按环境、权重、数据、许可证和依赖逐一验证。
5. Go1 相关研究先做离线分析和仿真，再研究 SDK/控制层接口；实机必须有人工监护、急停、速度限制、超时保护，不能让未经约束的 VLA 输出直接驱动机器人。
6. 服务器、内部 IP、访问令牌、终端隐私信息不得上传到公开仓库。大型权重/数据集只放外部资源链接，GitHub 仅存可公开的笔记、配置差异和脱敏报告。

## 推荐的每周工作节奏

| 时间 | 工作 | 可提交产物 |
|---|---|---|
| 周一 | 论文 A：摘要/引言/框架图/关键问题 | A 的结构化阅读笔记 |
| 周二 | 论文 B：方法/实验；与 A 和 2.0 对照 | B 的笔记与比较表 |
| **周三** | 补查公式/源码 + 汇总两篇 | **周报（必交）** |
| 周四 | 实现最小例子：伪代码、张量形状或开源项目目录分析 | 验证记录 |
| 周五 | 深读方法和实验，更新失败案例与下一周问题 | 补充笔记、Issue 勾选 |

**如何用 GitHub 作为学习主线：** 从 [8 周计划](ROADMAP-8-WEEKS.md) 找本周两篇论文 → 在 [进度表](PROGRESS.md) 标记 → 用 [模板](TEMPLATES.md) 提交笔记和周报 → 在 Issue/提交记录保留问题、证据和下一步 → 回到 [原复现路线](../docs/05-roadmap-and-evaluation.md) 验证是否推进了真实实验。
